# CLAUDE.md — ai-data-analyst-astra

SYNTHETIC analytics platform. Nothing here is Astra International data or systems.
Python ETL → Supabase PostgreSQL schema `dataset` → Looker Studio; n8n data assistant (Gemini);
Telegram alerts; Laya local decision engine. Start with [docs/00-project-overview.md](docs/00-project-overview.md),
progress in [docs/STATUS.md](docs/STATUS.md), human-only steps in [docs/HUMAN-STEPS.md](docs/HUMAN-STEPS.md).

## Commands (PowerShell or cmd, from the repo root)

All user-facing commands go through the launcher `astra.cmd`. Show them as `.\astra <command>`.

| Gate / task | Command |
|---|---|
| Syntax | `python -m compileall -q src tests` |
| Unit tests (offline, `.venv-laya`) | `.\astra test` |
| n8n tool SQL lint | `.\astra n8n lint` |
| n8n tools against the live DB (read-only) | `.\astra n8n check-live` |
| ETL smoke, no DB | `.\astra etl --dry-run --offline` |
| ETL dry run against the DB | `.\astra etl --dry-run` |
| DB connection | `.\astra check-db` |
| Telegram bridge config (no network) | `.\astra telegram-bot check` |

- ETL code runs on the system Python 3.12 (`requirements.txt`). Tests and Laya use `.venv-laya` (`requirements-laya.txt`).
- `astra.cmd` must keep CRLF line endings. After editing it, rewrite it with CRLF and check that
  `.\astra bogus` still exits 2.
- `n8n/build/` is generated by `.\astra n8n build`; never edit or commit it.

## Rules

- The repo is public. Never commit `.env`, `secrets/`, `raw-data/`, dumps, logs, the Supabase project ref,
  Telegram chat/thread/user IDs, tokens, passwords or private emails. Scan the staged diff before every commit.
- Never read `.env` through the shell or print its values. Use `.env.example` for variable names.
- Database changes: a new timestamped file in `sql/migrations/`; never edit an applied migration.
  Destructive SQL (DROP, TRUNCATE, mass DELETE/UPDATE), grants, RLS or role changes need the user's approval first.
- `astra_reporting` is read-only and has no access to PII columns. Looker Studio and n8n use only that role
  and only `dataset.v_*` views.
- The n8n assistant's LLM never writes SQL: every tool is a fixed, parameterized SELECT in `src/astra_n8n/assistant.py`.
- Telegram alerts carry counts only, never row data or PII. Ask before sending a test message.
- Nothing listens on a public interface. n8n (127.0.0.1:5698) and the Laya API (127.0.0.1:8765) stay on loopback.
  Telegram chat goes through the outbound-only bridge (`src/astra_bot`, doc 36), never a public webhook.
  The bridge never calls `deleteWebhook`.
- Update `docs/STATUS.md`, `docs/HUMAN-STEPS.md` and `docs/21-change-log.md` at each milestone.
